# Phase 1/2 — Definition of Done

## Purpose

This defines when the current conceptual discovery phase is sufficiently complete to begin a simplistic prototype.

It is a **good-enough gate**, not a claim that the model is finished.

## Transition

> From a promising collection of concepts and models to a sufficiently coherent generic model that can be implemented and tested in reality.

## Definition of Done

Phase 1/2 is done when:

- [ ] The purpose and generic scope of the Engine are understood well enough to build against.
- [ ] Identity → Transition → Identity survives the selected stress cases.
- [ ] Identity is understood as a context-dependent configuration rather than a fixed domain type.
- [ ] Opportunities and Obstacles/Constraints are understood as factors affecting transition without requiring domain-specific primitives.
- [ ] Strategic, Tactical and Operative are useful perspectives/layers rather than premature fundamental types.
- [ ] Motivation is understood as a driver of transition selection and size.
- [ ] Decision/commitment can be represented as a possible small or decisive Transition.
- [ ] Continuation / non-action can be represented as a possible choice.
- [ ] Mission / Task / Assignment has a clear relationship to Transition.
- [ ] Definition of Done has a clear relationship to Transition and Mission.
- [ ] Observation/feedback can represent what happened without prescribing the technical evidence mechanism.
- [ ] The two golden cases can be represented without domain-specific primitive types:
  - 18-year-old newcomer → software developer
  - Öland's Harvest Festival → desired future
- [ ] The final primitive-concept check finds no phenomenon requiring a new primitive.
- [ ] Known uncertainties and deferred questions are documented.
- [ ] The generic information model is coherent enough to guide a prototype.
- [ ] A first prototype can be specified without solving the entire future product.

## Explicitly not required

- final ontology
- database schema
- production API
- final UI
- complete AI architecture
- complete evidence/verification system
- complete matchmaking algorithm
- support for every possible domain
- complete KPI definitions
- production scalability
- commercialisation decisions

## Good-enough principle

A known imperfection does not block Phase 1/2 if it can be investigated more effectively through a prototype.

> **Good enough to build something real that can teach us more.**

The prototype itself becomes the next learning loop:

```text
Model v0.1
    ↓
Prototype
    ↓
Real use / observation
    ↓
Questions
    ↓
Decisions
    ↓
Model improvement
```
