# Application Principles

## A-001 — Start with the situation

Enter through something the user is trying to understand or change, not
through classification of the user.

## A-002 — No identity-type onboarding

Do not require the user to decide upfront whether they are an individual,
organisation, representative, team, community or something else.

## A-003 — Working scope over permanent role

The user works within a current scope. The scope may contain one or many
Things and may change over time.

## A-004 — Progressive complexity

Expose only the complexity needed for the next useful decision.

## A-005 — Uncertainty is valid

"I don't know" is a valid starting state. Help turn uncertainty into
possibilities rather than forcing premature intent.

## A-006 — Continuation is an alternative

Consider what may happen if prevailing dynamics continue. Doing nothing is
not treated as an error.

## A-007 — User chooses

The system and AI may suggest, compare and project. The user remains the
authority for the way forward.

## A-008 — Facts and projections must be distinguishable

Observed, reported, inferred and projected information must not silently
collapse into one another.

## A-009 — Show reasons, not just recommendations

When the system suggests a possibility or transition, the user should be able
to understand relevant information and assumptions.

## A-010 — One meaningful next step

Normally help identify the next meaningful transition rather than generating
a complete plan.

## A-011 — Multi-actor situations are normal

Support cooperation among multiple Things without requiring a special
workflow.

## A-012 — The interface is a projection of the model

The UI should expose useful views over the semantic model, not become its
source.

## A-013 — Prototype to discover

When the experience becomes awkward, treat that as evidence that either the
model or interaction needs reconsideration.
